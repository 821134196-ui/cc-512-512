# 叉车动力电池换电管理系统

班组在叉车作业间隙预约换电：扫码取下旧电池并交接 → 旧电池扫码入槽充电 → 扫码装上新电池 → 复核固定与可用电量。零第三方依赖，Python 3 标准库 + SQLite 实现。

## 启动（单条本地命令）

```bash
./run.sh            # 等价于 python3 app.py
# 可选：python3 app.py --port 8080 --reset
```

打开 <http://127.0.0.1:8000>。首次启动自动建库并生成演示数据与**过热样例**；加 `--reset` 可重置数据。

演示账号（右上角切换）：

| 账号 | 角色 | 权限 |
|---|---|---|
| `zhang` | 调度员 | 预约/取消换电，**不能**修改健康检测结论、不能处置故障槽位 |
| `li` | 维修人员 | 健康检测/隔离、过热复位、槽位故障隔离 |
| `wang` / `zhao` | 换电员 | 执行扫码换电（两账号用于并发冲突演示） |

## 内置样例

- **BAT-07 过热样例**：58.2℃ 触发过热保护、充电中断，池位图以 🌡 图标 + 「过热」文字 + 温度值标红，降温后由维修人员在「健康隔离」页复位；
- **BAT-09 动态过热**：充电过程中由模拟充电桩适配器再次触发热失控保护（启动后半分钟内）；
- BAT-10 健康隔离（鼓包，附本地检测照片）、BAT-11 SOH 65% 过低、BAT-12 充电中断未闭环、SLOT-05 槽位故障。

## 业务规则

**可用池六不入**：电池过热、槽位故障、充电中断、型号不兼容、错装、健康度过低（SOH < 80%），任一命中即退出可用池，换电页扫码安装会被事务拒绝。

**互斥绑定**：`bonds` 表中 `battery_id` 主键（一电池至多一条绑定）、`forklift_id`/`slot_id` 各有 UNIQUE（车/槽至多绑一块）、CHECK 保证一车一槽二选一；全部写操作走 `BEGIN IMMEDIATE` 事务 + WAL。两人并发扫同一块电池时，只有一人成功，另一人收到 409 并发冲突，两条扫码记录分别留痕「成功/拒绝」。

**换电工单状态机**：

```
已预约 → 换电中 → 待入槽 → 待安装 → 待复核 → 已完成
        （取下旧电池）  （旧入槽）  （装新电池）  （固定+电量）
```

## 页面

- **池位图**：可用池 / 充电槽位（编号、电量、预计充满时间）/ 在车电池 / 不可入池（附拦截原因）；
- **换电作业**：左旧电池、右新电池，三段扫码 + 固定/电量复核 + 交接流程时间线；
- **换电队列**：预约、开工、取消；
- **充电记录**：充满/中断（含过热保护、槽位故障原因）与电量；
- **健康隔离**：维修人员登记 SOH/结论/检测照片（存本地 `data/photos/`）、槽位故障处置、过热复位；
- **叉车状态**：车型/兼容型号/当前电池/电量温度，以及扫码交接流水。

充电桩信号（电压/电流/功率、电池电量与温度）由后台**模拟适配器**（`battery_swap/charger.py`）每 3 秒产生；真实接入时替换该适配器即可，业务层不变。

界面配色：工业白 + 深灰 + 少量电量绿；过热用红色图标、文字与温度值三重表达。

## 测试

```bash
python3 tests/test_swap.py        # 或 python3 -m unittest -v
```

覆盖：互斥绑定（主键/UNIQUE/CHECK 与完整换电流程）、型号兼容（车与槽两个方向）、错装标记、过热/低 SOH/中断/故障槽隔离、维修与调度员权限边界、模拟适配器过热保护与正常充满、两人并发扫码仅一人成功（服务层与 HTTP 层各一组）。
